# 既知の制約と未確認事項

この文書は、詳細な説明が他の文書に分散している制約を索引化します。「既知」は不具合の放置を意味せず、現在の設計で許容している制約、未実装、または現環境で証拠を取得していない事項を分けて示します。

## 設計上の制約

| 項目 | 状態 | 詳細 |
|---|---|---|
| 同期コードに失効・再発行機能がない | 未対応 | 漏洩時の完全な無効化手段はない。コード切替には残存データや旧端末の制約がある。 [sync.md](./sync.md#同期コード切替端末追加) |
| 認証アカウントがない | 設計 | 同期コードと allowlist がアクセス制御の中心。コードを知る相手への権限分離はない。 [security.md](./security.md#信頼境界とアクセス制御) |
| メモの値が平文で保存される | 設計 | 端末・サーバーとも暗号化しない。UI のマスクは表示上の配慮にすぎず、被害の大きい認証情報の保管には適さない。 [security.md](./security.md#メモに入れた値の扱いパスワードを含む) |
| 旧バージョンの端末にメモが「中身のないタスク」として出る | 制約あり | pull は同期コード配下の全行を返すため、`kind` を解釈できない端末ではメモが普通のタスクに見え、完了操作もできてしまう。サーバー側で防ぐ手段はない。メモを使い始める前に全端末を更新する。 [operations.md](./operations.md#デプロイ) |
| 通知の配信保証 | 設計 | 通知は best-effort。重複と端末ごとの欠落の可能性を完全には排除しない。 [notifications.md](./notifications.md) |
| Cron の D1 予算 | 既知の境界 | 候補処理は予算予約するが、候補の同期コードごとの購読 SELECT は予約前に走る。同期コード数が非常に多いと全 Cron の D1 文数上限を厳密には保証しない。 [invariants.md](./invariants.md#i-10b-cron-の候補処理は-d1外部-fetch-の予算で見送る) |
| 同期の再入ガード | 未対応 | 複数トリガが重なると重複 push があり得る。LWW と再送でデータ欠落を避ける設計。 [sync.md](./sync.md#未実装既知) |
| 退会・サーバー全削除の UI | 未対応 | 端末内整理と Push 停止はあるが、サーバー全削除の利用者向け導線はない。 [operations.md](./operations.md#バックアップとデータの取り扱い) |
| DST | 制約あり | `tz_offset` は端末が次に処理した時点で更新される。実機を含む境界確認が必要。 [recurrence.md](./recurrence.md#タイムゾーンの扱い) |
| 依存ライセンス | 要判断 | Web Push の推移依存に、利用許諾の確認が必要なものがある。法的な判断は人間が行う。 [security.md](./security.md#依存ライセンス) |

## 検証基盤の制約

| 項目 | 状態 | 必要な扱い |
|---|---|---|
| 自動テスト・lint・CI | 未導入 | 変更ごとに `npm run typecheck`、必要なら build/preview と手動確認を行う。 [development-workflow.md](./development-workflow.md) |
| 実機 Push / PWA | この文書作成時点では未確認 | iOS、Android、デスクトップでの購読・通知・クリック・SW 更新を、実機で確認して結果を残す。 |
| 本番 Cloudflare 設定 | この文書作成時点では未確認 | allowlist、Cron、D1 schema、Pages 設定、Secrets の値を公開文書から推測しない。人間が管理画面で確認する。 |
| 本番データ | 意図的に未参照 | 開発・検証では隔離したデータのみを使う。バックアップやログを公開文書へ貼らない。 |

## 公開・運用上の制約

| 項目 | 状態 | 必要な扱い |
|---|---|---|
| Cloudflare Free の上限 | 外部仕様で変動し得る | 正式な上限は [security.md](./security.md#クラウドサービスの上限) の公式リンクを再確認する。上限到達時はエラーになり得る。 |
| ログの機密性 | 注意が必要 | Push endpoint やタスク識別子がログに含まれ得る。閲覧権限、共有、スクリーンショットを人間が管理する。 [operations.md](./operations.md#監視とログ) |
| 手動デプロイ | 設計 | CI/CD はなく、本番への反映・ロールバック・記録は人間が判断して行う。 [operations.md](./operations.md#デプロイ) |
| バックアップ | 注意が必要 | D1 export は平文の利用者データを含み得る。保存、暗号化、保持、廃棄、復元試験の方針を人間が決める。 [operations.md](./operations.md#バックアップとデータの取り扱い) |

新しい制約を発見したときは、詳細を担当文書へ追加し、この索引にも状態とリンクを追加してください。既知の制約を解消した場合は、実装・検証根拠を確認してから状態を更新します。
