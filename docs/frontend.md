# フロントエンド

## 画面構成

| ルート | ページ | 内容 |
|---|---|---|
| `/` | `ListPage` | タスクとメモの一覧。プロジェクト単位のグルーピングと並べ替え |
| `/report` | `ReportPage` | 週間達成率・ストリーク・完了ヒートマップ・プロジェクト別内訳・定量タスク一覧 |
| `/settings` | `SettingsPage` | 同期・表示・通知・データ・フィードバックの 6 セクション |

`Layout` が `lg` ブレイクポイント（1024px）でサイドバー／下部ナビを切り替えます。

`App.tsx` はルータに加えて、起動時の同期・繰り返し復活・ローカル通知のトリガを持ちます。

| トリガ | 実行するもの |
|---|---|
| 起動時 | `runSync()` + `reviveRecurringTasks()` + `fireDueLocalNotifications()` + silent `subscribePush()` |
| `online` イベント | `runSync()` + silent `subscribePush()`（購読の自己修復） |
| 5 分間隔（`SYNC_INTERVAL_MS`） | `runSync()` |
| `visibilitychange` | `reviveRecurringTasks()` + `fireDueLocalNotifications()`（**`runSync` は呼ばない**） |
| 30 秒間隔（`LOCAL_NOTIFY_INTERVAL_MS`） | 同上 |

## 状態管理

**専用の状態管理ライブラリは使っていません。** Dexie の `useLiveQuery` が IndexedDB の変更を購読して
再描画するため、それが実質的なストアです。

```ts
const tasks = useLiveQuery(() => db.tasks.where('sync_code').equals(code).toArray(), [code]);
```

書き込みは `src/lib/taskRepo.ts` の関数を通します（直接 `db.tasks.put` を呼ばない）。
`taskRepo` が `updated_at` の更新・完了ログの追記・`scheduleSync()` の発火をまとめて面倒を見ます。

端末固有の設定（ダークモード・文字サイズ・ソート順・プロジェクト展開状態）は
`src/hooks/` の各フックが LocalStorage と同期します。

## エラーバウンダリ（`src/components/ui/ErrorBoundary.tsx`）

pull はサーバー応答を**正規化せずに** Dexie へ入れます（`sync.ts` の `db.tasks.put(serverTask)`）。
サーバーは中身を解釈しないので、別バージョンのクライアントが書いた形や壊れた値がそのまま
描画まで届く経路が実在します。React は捕まえない例外でツリー全体をアンマウントするため、
**カード 1 枚の失敗で画面が真っ白**になり、設定画面にも辿り着けません（＝再同期もデータ管理も
できない）。ユーザーからは「データが全部消えた」ようにしか見えません。

2 段で囲みます。

| 段 | 場所 | fallback |
|---|---|---|
| 画面 | `Layout` の `<Outlet />` | 「画面を表示できませんでした」＋ もう一度表示 / 再読み込み / **設定へ**。`resetKey` はルートのパスなので、タブを移れば自動で復帰を試みる |
| カード | `ProjectGroup` のカード 1 枚ずつ | `CardErrorFallback`（タイトル＋もう一度表示＋このタスクを削除）。他のカードは生きたまま |

**通常時に DOM を足さないこと。** `ErrorBoundary.render()` は例外が無いあいだ `children` を
そのまま返します。ラッパー要素を 1 段挟むと `useFlipReorder` が壊れます
（あちらは `listRef` の**直接の子**の `data-task-id` を読むため）。fallback 側も
`data-task-id` を保ちます。

`resetKey` にカードの `updated_at` を渡してあるので、同期で新しい版が届けば自動で描き直しを試みます。
`CardErrorFallback` はタイトルを `String()` で包みます — 壊れた行が原因でそこに居る以上、
`title` が文字列である保証も無く、fallback 自身が投げると今度は画面全体の境界まで例外が上がります。

## タスク

### 種別

| 種別 | 内容 |
|---|---|
| `simple` | タイトル + リマインダー + 繰り返し |
| `quantitative` | 目標値に対する進捗を加算で記録（「30 ページ読む」「10km 走る」） |

定量タスクの操作:
- **チェックボックス** → 「進捗を記録」モーダル（delta 加算）
- **数値をタップ** → 直接書き換え

### 期限（`due_date`）

**表示専用メタデータ**で、**通知には一切関与しません**。設定できる場所は 3 つあります。

| 場所 | 用途 |
|---|---|
| 追加・編集フォームの「期限を設定」トグル | 作成時にその場で決める |
| タスクカードの三点メニュー「期限を設定」 | 期限が無いタスクに後から足す |
| カード右端の期限ピル | 既にある期限を変える |

期限なしの状態から開いた場合は「今日 23:59」を初期値として表示します。
これは iOS Safari が空の日時入力を空欄として描画してしまい、日時欄だと分からなくなるためです。

**繰り返しとは排他です。** `taskRepo` の `buildTask` が「期限があれば繰り返しを落とす」、
フォームの `handleRecurrenceToggle` が「繰り返しを ON にしたら期限を外す」を担います。
以前はフォームに期限欄が無かったため、**繰り返しを ON にした瞬間に期限が黙って消え**、
ユーザーは一覧へ戻って期限ピルが無くなって初めて気づく状態でした。現在は繰り返し ON の間
期限トグルを無効化し、「繰り返しと期限は同時に設定できません」と理由を出します。
**排他のルールそのものは変えていません**（可視化しただけ）。

フォームの期限欄には「期限は表示専用です。その時刻に通知するには、下のリマインダーを
設定してください」を添えます。カード上ではカレンダーアイコン（期限）とベル（リマインダー）の
違いしか手がかりが無く、両者の役割差が読み取れなかったためです。

入力を空にしたときは `null`（＝期限 OFF）にせず空文字を渡し、欄を保持したまま
バリデーション（V-4）で送信を止めます（リマインダー欄と対称）。

### ソフト削除

`status = 'deleted'` として保持し、365 日後にクリーンアップで物理削除します。
これにより「削除した」という事実が他端末へ同期されます（行を消すと同期で復活してしまう）。

### チェックボックス色

15 色 + 「自動」。既定はスレート（灰色）。「自動」（`color = null`）を選ぶと種類 × 期限で配色します
（`src/lib/taskColors.ts`）。

**動的に組み立てる Tailwind クラスは purge されるため**、`tailwind.config.ts` の safelist に
`COLOR_SAFELIST` として登録しています。色を追加するときは `taskColors.ts` と safelist の両方を更新してください。

### サブタスク（折りたたみチェックリスト）

1 つの用事を複数の手順に分けて記録するための、タスク内のチェックリストです。
**`simple` タスクだけが持てます**（定量タスク・メモは対象外）。データの持ち方は
[data-model.md](./data-model.md#サブタスクは親行の-1-列に入る) を参照してください。

**折りたたみが既定。** カードの情報密度を上げないことが目的なので、展開状態は
**永続化しません**（プロジェクトの展開状態を `todo_project_states` に保存しているのとは
別の判断です）。畳んだ状態では次の 2 つだけを出します。

| 要素 | 位置・見え方 |
|---|---|
| 進捗 `2/4` とシェブロン | 期限ピルの左。押すと開閉する |
| 細い進捗バー（`h-1`） | タイトルの直下。色は親のアクセント色を継承 |

定量タスクのバー（`h-1.5`・数値がバーの上）とは高さと数値の位置で見分けます。サブタスクは
`simple` 限定なので同じカードに 2 本並ぶことはありませんが、一覧では混在します。

**展開の導線はシェブロンボタンだけにします。** カード面のタップはスワイプ（横）と長押しドラッグ
（`@dnd-kit`）の起点を兼ねており、ここに展開を足すとスワイプを途中でやめただけで誤って開きます。

開閉は `grid-template-rows` の `0fr → 1fr` で行います（中身の高さを測らずに開閉でき、閉じる側も
アニメーションする）。`prefers-reduced-motion` では即座に切り替わります。並び順の変化ではないため
`useFlipReorder`（`listRef` 直下の `data-task-id` を見る）は走らず、下のカードはこの高さ変化に
自然に追従します。

**完了済みの子はその場に残します**（下部へ寄せない）。順序が動かないので「手順」として読め、
誤タップで付けたチェックを戻す位置も分かります。連続でチェックしたときに行が飛んでタップ位置が
ずれることもありません。見た目は取り消し線 + `opacity-50`。

#### 親タスクとの連動

| 操作 | 結果 |
|---|---|
| 子が全部完了した | **親も自動的に完了する。** 定量タスクが目標値に達したら自動完了する挙動と同じ考え方 |
| 全部完了の状態から子のチェックを外した | **自動完了を取り消して未完了へ戻す**（自動完了のちょうど逆操作）。完了ログも対にして取り下げる |
| 親をチェックした | **子は一切触らない。** 完了は「もう終わったことにする」宣言であって、手順の記録を書き換える操作ではない |
| 親を明示的に未完了へ戻した | **子のチェックを全て外す**（`uncompleteTask`）。繰り返しの周期復活と同じ「やり直し」の扱い |
| 未完了の子を残したまま親を完了させようとした | 確認ダイアログを出す。承諾後も子のチェックはそのまま残る |
| 未完了の子を残したまま完了させたタスクの子を触った | **completed のまま**。ユーザーが明示的に「もう終わったことにする」と決めた判断を、子の操作で覆さない |
| 完了済みタスクを編集して未完了の子が生じた | 未完了へ戻す（完了済み定量タスクの現在値を目標未満へ編集したときと対称）。完了ログも取り下げる |
| 繰り返しタスクが周期境界で復活した | 子のチェックを全て外す（[invariants.md](./invariants.md#i-1-繰り返しタスクの-status-復活はクライアント専任)） |

**「完了 → 未完了」だけが非対称なのはなぜか。** 完了させるときに子を触らないのは、`2/4` のまま
「もう終わったことにする」と決めた判断を、アプリが勝手に埋めてはいけないからです。一方で
未完了へ戻す操作は「もう一度やる」という宣言なので、繰り返しタスクが周期境界で復活するとき
（[I-1](./invariants.md#i-1-繰り返しタスクの-status-復活はクライアント専任)）と同じく、子も最初からやり直しにします。
`2/4` で完了させたタスクを戻すと、その 2 件のチェックも消えます。承知のうえの割り切りです。

**このリセットを他の「復活」経路へ広げないこと。** `uncompleteTask()` の中だけで行います。

| 広げてはいけない経路 | 広げると何が起きるか |
|---|---|
| `toggleSubtask()` の自動取り消し | 子 1 個のチェックを外しただけで、他の子のチェックが全部消える |
| `addSubtask()` / `updateTask()` の復活 | 手順を 1 つ足しただけで、既存のチェックが消える |
| `restoreTask()` | 削除の取り消しは完了状態の**復元**であって、やり直しではない |

**サブタスクの完了は `completions` に記録しません。** サブタスクは親タスクの内部状態であって
達成の単位ではないため、レポートの各指標の母集団は変わりません。
記録するのは親タスクの完了だけです（自動完了も含む）。

**右スワイプ完了との調停**: 未完了の子が残るタスクは `commitRightBehavior` を `'spring'` にして
カードをその場に戻してから確認ダイアログを出します。飛んでいくカードの上にダイアログを出すと、
キャンセルしたときの戻し先がありません（未完了の定量タスクで進捗モーダルを開くときと同じ扱い）。

#### カード上での追加・編集・削除

展開したリストからフォームを開かずに手順を足せます（`+ サブタスクを追加`）。Enter で確定すると
入力欄は開いたままなので、思いついた順に続けて打てます。完了済みタスクに未完了の手順を足したら
`active` へ戻します。

各行の右端に**三点メニュー（編集 / 削除）**を置きます。親タスクと同じ導線を子にも用意する形です。

| 項目 | 挙動 |
|---|---|
| 編集 | その行がその場で入力欄に変わる（`renameSubtask`）。Enter / フォーカスアウトで確定、Escape で破棄。**空文字で確定した場合は削除ではなく破棄**（元のタイトルに戻す）。`done` と親の `status` には触らない |
| 削除 | `removeSubtask` ＋ 5 秒の取り消しトースト（`restoreSubtask` が**元の配列位置ごと**戻す）。**削除では親を自動完了させません**（残りが全部完了になっても、削除は進捗の記録ではなく構造の編集なので） |

**メニューは常時表示です。** 以前の削除ボタンは `group-hover` で現れる形でしたが、
タッチでは発見できず、当たり判定だけが残って隣の要素と取り合っていました。
sticky hover で「行の 1 タップ目が hover に消える」経路にもなりえます
（[タッチ端末の hover](#タッチ端末の-hover)）。

**メニュー本体は `document.body` へ portal します**（`src/components/ui/AnchoredMenu.tsx`）。
行は展開アニメーション用の `overflow-hidden` の内側にいるため、その場に `absolute` で置くと
リストの下端で切り取られます（[P-17](#落とし穴集不変条件ではないが知らないと踏むもの) と同じ事情）。
トリガの `getBoundingClientRect()` から `position: fixed` で置き、下に入らなければ上向きに開きます。
カード面が静止時に `transform` を持たない約束には依存しません（カードの外に出るため）。

`AnchoredMenu` は **`role="menu"` / `role="menuitem"` を名乗りません。** あれは矢印キー・Home/End・
roving tabindex の実装を前提にした役割で、それを見たスクリーンリーダーはブラウズモードを抜けて
矢印キーをウィジェットへ委ねます。モデルを実装せずに名乗ると、利用者は矢印で項目を辿れないまま
操作手段を失う——**名乗らない方が操作性が良い**。素の `<button>` の並びとして出し、トリガ側の
`aria-haspopup` / `aria-expanded` / `aria-controls` で関係だけを伝えます。
`TaskCard` / `MemoCard` / `ProjectGroup` の三点メニューは従来のまま（`role="menu"` 付き）で、
揃えるなら別変更です。

#### 並べ替えは持たない

サブタスクの並び順は配列順のままで、**カードでもフォームでも変えられません**。
以前は専用のグリップハンドルから `@dnd-kit` で並べ替えられましたが、カード面が既に
「縦スクロール」「横スワイプ」「カード自体の長押しドラッグ」を取り合っており、そこへ 4 つ目の
ジェスチャを重ねる価値が薄いため撤去しました。`taskRepo.reorderSubtasks()` も削除済みです。

代わりに**リスト全体へ `data-swipe-ignore` を付けています。** チェックリストの上を横になぞって
カードごと完了・削除されるのを防ぐためです（`useSwipeAction` は根に張った **native** リスナで
React より先に走るので、React の `stopPropagation` では降ろせません。印を見て降りてもらいます）。

#### 畳んでいる間は tab 順から外す

折りたたみは `grid-template-rows` の `0fr` で高さを 0 にしているだけなので、**見えていなくても
中のボタンにフォーカスが入ります。** `SubtaskList` は `expanded` を受け取り、スワイプパネルと
同じ流儀（`tabIndex={expanded ? 0 : -1}` ＋ `aria-hidden`）で塞ぎます。

## メモ

電話番号・メールアドレス・パスワードなど、**チェックして完了させるものではない情報**の控えです。
タスクの兄弟エンティティで、実体は `tasks` ストアの `kind === 'memo'` の行です（[data-model.md](./data-model.md#メモは-tasks-に同居する)）。

| 項目 | 内容 |
|---|---|
| 構造 | タイトル ＋ 値 ＋ 種類（電話 / メール / パスワード / その他）の 1 対 1 |
| 種類の定義 | `src/components/memo/memoTypes.ts` に集約（ラベル・アイコン・`inputMode`・マスクの有無）。**種類を増やすときはここだけ**（サーバー側の変更は不要） |
| 書き込み | `src/lib/memoRepo.ts` の `createMemo` / `updateMemo` / `deleteMemo`（`taskRepo` と同じ流儀。直接 `db.tasks.put` を呼ばない） |
| 削除 | タスクと同じソフト削除（`status='deleted'`） |

### 一覧では**タスクと混在する**

切替 UI は置きません。同じプロジェクトのグループに、タスクとメモが同じ列で並びます。
種別の手がかりは**行頭のアイコンだけ**です。

| | 行頭 |
|---|---|
| タスク | 丸チェックボックス（`h-6 w-6 rounded-full border-2`） |
| メモ | **縁を描かない**コピーアイコン（`lucide-react` の `Copy`） |

コピーボタンに丸い縁を付けないのは、タスクの未完了チェックと同じ輪郭になり「押すと完了する」と
誤読されるためです。占有幅（`h-6 w-6`）と擬似要素による当たり判定の拡大（`before:-inset-2`）だけ
タスクカードに揃えて、行頭の位置とタップしやすさを保っています。

メモは `status` が常に `active` なので、既存の `sortTasksInGroup` の active 群にそのまま入り、
**タスクと混ぜたまま同じグループ内でドラッグ並べ替えできます**（`reorderTask` は無改造）。

### 件数は**タスクだけを数える**

メモは完了の概念を持たず常に `active` です。`active` を数えている箇所からメモを外さないと、
未完了タスクが 0 のプロジェクトでも「未完了 N件」と表示されます。対象は 3 箇所:

| 箇所 | 表示 |
|---|---|
| `src/hooks/useProjects.ts` の `remaining` | プロジェクトチップの残り件数、一覧ヘッダーの「未完了 N件」 |
| `src/components/project/ProjectGroup.tsx` | グループ見出しの「完了/全体」 |
| `src/lib/reports.ts` の `getWeeklyCompletionRate` | 週間達成率の分母 |

### コピーとマスク

- コピーは `navigator.clipboard.writeText` ＋ トースト（`SyncCodeCard` と同じパターン）。
  **伏せ字のままでもコピーできます**（パスワードを画面に出さずに使えるように）。
- 種類が「パスワード」のときだけ値を固定長の伏せ字（`••••••••`）で表示し、目のアイコンで切り替えます。
  長さを漏らさないよう伏せ字の桁数は実際の値と無関係に固定です。
- **表示状態は永続化しません。** カードのローカル state なので、画面を離れて戻れば必ず伏せ字へ戻ります。
- 値は等幅フォントで表示します（`0` と `O`、`1` と `l` を読み違えないため）。
- フォームの各入力に `autoComplete="off"` を付け、ブラウザのパスワードマネージャに保存を提案させません。

### 追加フォームでの切替

追加ボタン（FAB）は 1 つのままで、**フォームの先頭**に「タスク / メモ」のセグメントがあります
（`src/components/task/entryKind.ts` に選択肢を集約）。**新規作成時のみ表示**し、編集時は隠します
（タスクの「編集時は種類を変更できません」と同じ考え方）。`ListPage` が `formEntity` を持ち、
`TaskFormDialog` と `MemoFormDialog` を出し分けます。編集時は対象行の `kind` から開くフォームを決めます。

> 種別を切り替えるとダイアログが差し替わるため、モバイルでは BottomSheet が一度アンマウントされて
> 高さが測り直されます。空のフォームでの切替なので影響は小さい想定ですが、実機で不自然に見えるようなら
> `FormDialog` の外殻を共有する形へ寄せる余地があります（`TaskFormDialog` の検証ロジックを持ち上げる改修が要る）。

### 通知には一切関与しない

メモは `reminder_time` / `reminder_offset` / `recurrence_rule` / `due_date` をすべて `null` で保存するため、
通知 Cron の候補クエリにも、起動中のローカル通知（`offlineNotify.ts` の `if (!t.reminder_time) continue;`）にも
載りません。

## プロジェクト

**プロジェクトは独立したエンティティではありません。** `project_name` の文字列一致による派生表示です。

- グルーピングは文字列一致のみ。ID を持たない
- プロジェクトヘッダーの「…」メニューからいつでもリネームできる
- 既存の別名と同名にすると**1 つに統合される**（統合になる場合は保存前にダイアログ内で警告）
- 展開／折り畳み状態は端末ごとに LocalStorage（`todo_project_states`）で保持
- 「その他」（未分類）は表示順設定に関わらず常に最下部

### 既知の制約: 多端末でのリネーム競合

安定 ID を持たないため、オフライン端末がリネーム前に旧名でタスクを編集し後から同期すると、
**その端末発のタスクだけ旧名グループとして再出現**します（データ消失はなく、再度リネームすれば統合されて解消）。

同様に、行単位 LWW のため、リネームより古いオフライン編集はリネームに上書きされて失われえます
（既存の編集競合と同じ挙動が、プロジェクト単位でまとめて起きるだけ）。

## 並び順

**2 系統あるので混同しないこと。**

### 1. プロジェクト（グループ）の表示順 — `todo_sort_order`

作成日時（新しい/古い順）、タスク数（少ない/多い順）、名前（五十音順）の 5 種。
**この設定はプロジェクトの並び順にだけ効きます。タスクの並びには効きません。**

タスクの完了・削除で件数などが同点になった場合は、意図しない並び替えに見えないよう前回の表示順を維持します。
選択 UI はネイティブ OS の `<select>`（端末標準のピッカーで操作できるため）。

### 2. プロジェクト内のタスク順 — `sort_order` 列

未完了タスクは**ドラッグで手動並べ替え可能**です。

| 項目 | 内容 |
|---|---|
| ライブラリ | `@dnd-kit`（core / sortable / utilities） |
| 開始条件 | デスクトップ = 8px ドラッグ（MouseSensor）／モバイル = 200ms 長押し（TouchSensor） |
| 範囲 | プロジェクト内限定・跨ぎ不可（「その他」でも可） |
| 永続化 | `sort_order`（表示は**降順** = 大きいほど上）。**移動した 1 行だけ**に隣接中間値を書く（fractional 採番） |
| 精度枯渇時 | `renumberActive()` で全件リナンバー |
| 未設定時 | `created_at` にフォールバック（従来の並びと一致・マイグレーション不要） |
| 新規タスク | 常に最上部（`Math.max(now, active の最大 effective + 1)` を割り当て） |
| 完了タスク | 未完了の下。**最新完了が上・最初に完了したものが最下部**（`updated_at` 降順） |

表示キーは `effective = sort_order ?? created_at`。同期層は無変更で既存の round-trip に相乗りします
（サーバーは `sort_order` を解釈しない）。

> `sort_order` は INTEGER 列ですが、fractional 採番のため実際には REAL が入ります
> （SQLite の型アフィニティに依存）。

### アニメーション

| 種類 | 担当 |
|---|---|
| ドラッグ中の押しのけ | `@dnd-kit` |
| 完了で沈む等の非ドラッグ変化 | `useFlipReorder`（FLIP） |

`useFlipReorder` は `enabled` 引数を持ち、ドラッグ中〜楽観 override 中は無効化します（二重アニメーション防止）。
個別の要素に `data-flip-skip="true"` が付いている回は、その要素だけ FLIP を譲ります
（自前の登場アニメを持つカードと縦スライドが重なって斜めに飛ぶのを防ぐため。下の[スワイプ操作](#スワイプ操作srchooksuseswipeactionts)で使っています）。
どちらも `prefers-reduced-motion` を尊重します（`src/lib/motion.ts`）。

## スワイプ操作（`src/hooks/useSwipeAction.ts`）

タスクカードを**右へスワイプすると完了、左へスワイプすると削除**できます。三点メニューと
チェックボックスの従来経路はそのまま残してあり、スワイプを唯一の操作経路にはしていません。

| 対象 | 右スワイプ | 左スワイプ |
|---|---|---|
| 未完了のタスクカード | 完了 | 延期 ＋ 削除 |
| 未完了でも繰り返し／リマインダー無し | 完了 | 削除のみ |
| 完了済みのタスクカード | 未完了に戻す | 削除のみ |
| メモカード | コピー | 削除のみ |

**右スワイプの色とラベルは対象で変わります**（完了 = ブランドのティール ＋「完了」、未完了に戻す =
`slate-600` ＋「未完了に戻す」、コピー = ティール ＋「コピー」）。左は常に赤の「削除」で、
延期だけ `sky-700` を使います。

**確定の仕方は方向で変えています。** 右（完了）はカード幅の 45% を超えて指を離した時点で即実行、
左（削除）は即実行せずアクションボタンへスナップし、ボタンをタップして確定します。
破壊的な操作ほど段を増やすためです。完了は取り消しトーストを出さないので、しきい値は
削除より深く取っています（`useSwipeAction.ts` の `COMMIT_RATIO`）。パネルが開いている間は
カード面へのタップを「閉じる」に振り替えます（ずれた位置のチェックや期限ピルを誤って押させないため）。

### 完了の見せ方（右へ抜けて、右から戻る）

タップでの完了は「チェックが弾んでから沈む」、スワイプでの完了は**カードが戻らずそのまま右へ抜け、
完了群に画面右側から入ってくる**という違いだけを持ちます。ばね戻しさせてから完了させると
「やり切った」感が出ないためです。

| 段階 | 動き | 実装 |
|---|---|---|
| 1. 抜ける | カード面を枠の外まで `translateX`（240ms・加速イージング）。アクション背景は出したまま | `useSwipeAction` の `commitRightBehavior: 'fly'` |
| 2. コミット | 抜けきってから `completeTask()` を呼ぶ | `TaskCard` の `startCompletion(FLY_OUT_MS, …)` |
| 3. 戻る | 完了群の位置に `translateX(100%)` から入る（300ms） | `global.css` の `.task-fly-in` |

この演出は**完了と「未完了に戻す」の両方**に効きます。どちらもカードが一覧の別の場所へ移り、
`SortableTaskCard` ↔ `TaskCard` の差し替えを伴って**別インスタンスとして再マウント**されるためです。
「右へ抜けた」という文脈を props で渡せないので、`TaskCard.tsx` のモジュールスコープに
`swipeMovedAt`（id → 時刻）を置いて受け渡しています。1.5 秒を過ぎた記録は使いません。

登場中のカードには `data-flip-skip="true"` を付けて `useFlipReorder` の縦スライドを止めます。
止めないと「下へ滑る」と「右から入る」が重なって斜めに飛び、消えたはずのカードが元の位置から
現れたように見えます。周りのカードが詰まる動きは従来どおり FLIP が補間します。

**カードがその場に残る操作では抜けさせません**（`commitRightBehavior: 'spring'`）。
未完了の定量タスク（右スワイプで開くのは進捗モーダルで、完了するとは限らない）と、
メモのコピーが該当します。

書き込みは `TaskCard` の `startCompletion()` に一本化してあり、タップもスワイプも同じ経路を通ります。
繰り返しタスクの完了ログ追記・二重実行ガード・`scheduleSync()` をまとめて担保するため、
**スワイプから `db.tasks.put` を直接書いてはいけません**。

### 削除と取り消し

削除は確認ダイアログではなく**取り消しトースト**で受けます（5 秒）。ソフト削除なので
`status` を戻すだけで復元でき、[ゴミ箱 UI がない](#未実装既知)問題の部分的な解消にもなります。
カードは完了と同じく左へ抜けさせてから書き込みます。

- `showToast(text, kind, { action, durationMs })` の第 3 引数でアクションボタンを付けます。
  既存の 2 引数呼び出しは無改造で従来どおり（3000ms・ボタンなし）です。
- 復元は `taskRepo.restoreTask(id, previousStatus)`。メモも `tasks` の行なので同じ関数で戻します。
- **`status` が `'deleted'` でない行には触りません。** トーストが出ている数秒の間に他端末の pull が
  届いて復活・再編集されている可能性があり、そこへ古い `status` を上書きすると LWW で相手の変更を
  消してしまいます。
- `sort_order` は削除時に触らないため、`active` へ戻せばプロジェクト内の元の位置に戻ります。
  `completed` へ戻す場合は `updated_at` が進むぶん完了群の最上部へ移ります（完了群は `updated_at` 降順）。

アクションボタンの幅は文字サイズ設定で変わるため実測します。スワイプが始まってから描画したのでは
最初の 1 フレームぶん指に追従できないので、パネルは常に置いて `invisible` で隠し、
開いていない間は `tabIndex={-1}` / `aria-hidden` で支援技術とキーボードから外します。
スナップ位置はラベル 1 つぶんの実測幅 × ボタン数です。

### 延期（`SnoozeSheet`）

「延期」は**単発タスクのリマインダーを先送りするだけ**の操作です。`taskRepo.snoozeTask()` が
`reminder_time` だけを書き、**`due_date` には触りません**。期限は通知に関与しない表示専用
メタデータであり、ユーザーが決めた締切を延期操作が黙って書き換えないためです。

**繰り返しタスクには出しません。** 繰り返しの `reminder_time` は「周期境界 − `reminder_offset`」から
導出される値なので、手動の値を入れても `reviveRecurringTasks()` とサーバー Cron の前進計算に
上書きされて延期が消えます（[recurrence.md](./recurrence.md)）。カード側で導線を隠したうえ、
`snoozeTask()` でも防御的に no-op にしています。繰り返しでも延期したい場合は `snooze_until` の
ような別列と Worker 側の対応が必要で、これは「UI の改善」ではなく通知アーキテクチャの変更になります。

導線を出す条件は「未完了 かつ `recurrence_rule === null` かつ `reminder_time !== null`」です。
満たさないカードは左パネルが削除の 1 段だけになります。**同じ条件で三点メニューにも「延期」を出します**
（スワイプを唯一の操作経路にしない）。

シートは `FormDialog`（PC=Modal / モバイル=BottomSheet）で、「1時間後」「3時間後」「明日の朝 8:00」を
1 タップで確定し、下部の `datetime-local` で任意の日時も選べます。**プリセットの基準は「今」であって
現在のリマインダー時刻ではありません**（「通知が来たが今できない、後で」が主な用途のため）。
任意日時は既存のリマインダー入力と同じ規則（今から `REMINDER_MIN_LEAD_TIME_MIN` 分以上先）で検証します。

延期すると `reminder_time` が変わるので、ローカル通知の重複排除キー（`${id}@${reminder_time}`）も
サーバーの claim（`(task_id, reminder_time)`）も別物になり、新しい時刻で改めて通知されます。

### 3 つのジェスチャの排他（@dnd-kit との調停）

同じカードの上で「縦スクロール」「長押しドラッグ並べ替え」「横スワイプ」が競合します。

`ProjectGroup` の `TouchSensor` は `{ delay: 200, tolerance: 5 }` です。`@dnd-kit/core` の
`AbstractPointerSensor.handleMove` は、delay 経過前に移動距離（ユークリッド）が tolerance を超えると
`handleCancel()` を呼び、**そのタッチではドラッグを再開しません**（`@dnd-kit/core` 6.3.1 の実装で確認、
2026-08-16）。これを利用して次のように振り分けます。

| 指の動き | 勝つジェスチャ |
|---|---|
| 200ms 以内に 5px 超動いた → さらに 10px 超、かつ `\|dx\| > \|dy\| × 1.5` | 横スワイプ |
| 200ms 以内に 5px 超動いたが、縦寄り | 縦スクロール（以後スワイプ判定しない） |
| 5px 以内のまま 200ms 経過 | 長押しドラッグ（@dnd-kit） |

`useSwipeAction.ts` の `DND_DELAY_MS` / `DND_TOLERANCE_PX` は
**`ProjectGroup.tsx` の `activationConstraint` と同値に保つこと。** 片方だけ変えると調停が破れます。

カードには `touch-action: pan-y` を指定して、横方向のブラウザ既定動作を止めます。

### カード内の操作ボタンは長押しドラッグに参加させない（`stopCardDrag`）

カードの根そのものがドラッグの起点です（`SortableTaskCard` が `{...attributes, ...listeners}` を
`TaskCard` の根 div へ撒いています）。そのため **5px 以内で 200ms 静止したタッチ**——小さい的を狙って
丁寧に押す動作そのもの——でドラッグが成立します。

そして `@dnd-kit/core` の `AbstractPointerSensor.handleStart()` は、成立した瞬間に
**`document` の capture 段階へ `click` → `stopPropagation` を登録します**（外れるのは `detach()` の
50ms 後。`@dnd-kit/core` 6.3.1 の実装で確認、2026-08-30）。結果、指を離した直後の click が React の
ルートへ届く前に握り潰され、ボタンの `onClick` が呼ばれません。ユーザーからは
**「1 回タップしても反応せず、もう一度タップすると効く」**に見えます。

`onClick` の中の `stopPropagation()` では止まりません（相手は document の capture リスナで、React の
合成イベントより先に走ります）。**タッチが始まる時点で親へ渡さない**のが唯一の手です。
`src/components/task/stopCardDrag.ts` を、カード内の操作要素の `onTouchStart` に付けます。

| 対象 | 要素 |
|---|---|
| `TaskCard` | チェックボックス、`2/4` シェブロン、期限ピル、三点メニュー、スワイプパネルの延期・削除・「操作を閉じる」 |
| `MemoCard` | コピー、目のアイコン、三点メニュー、スワイプパネルの削除・「操作を閉じる」 |
| `QuantitativeProgress` | 現在値のタップ編集 |
| `SubtaskList` | トグル、三点メニュー、追加ボタン、インライン入力欄 |

**`onMouseDown` は止めません。** `MouseSensor` は `{ distance: 8 }` で delay を持たず、実際に 8px
動かすまでドラッグは成立しないため click も殺されません。デスクトップでカード面のどこからでも
並べ替えを始められる現状を変える理由がありません。

**この対策は `useSwipeAction` には効きません**（あちらは native リスナで React より先に走るため）。
横スワイプの対象から外したい領域には `data-swipe-ignore` を付けます。

### タッチ端末の hover

`tailwind.config.ts` に `future: { hoverOnlyWhenSupported: true }` を設定し、すべての `hover:` を
`@media (hover: hover) and (pointer: fine)` で包んでいます（Tailwind 3.4.19 のビルド出力で確認、
2026-08-30）。これが無いとタッチ端末では hover が **「タップした瞬間に付き、次にどこかを触るまで残る」**
sticky hover になり、押した要素が「選択中」に見えます。

加えて、iOS Safari には「hover で見た目が変わる要素は 1 タップ目を hover の適用に使い、click を
送らない」という挙動が知られています（**未確認**: 本アプリの実機では再現確認していません。
`stopCardDrag` で潰した [@dnd-kit の click 握り潰し](#カード内の操作ボタンは長押しドラッグに参加させないstopcarddrag)
のほうは、ライブラリ実装を読んで確認済みです）。

したがって **hover でしか現れないコントロールを作らないこと。** タッチでは発見できないうえ、
その要素を含む行のタップを 1 回余分に食います。

### 実装上の制約（変更時に踏みやすい）

- **カードを外側で包めません。** `useFlipReorder` は `listRef` の**直接の子**の `data-task-id` を読みます。
  そのためスワイプ層はカード根 div の**内側**に作ります（背景のアクション層 ＋ `translateX` するカード面の 2 層）。
- **アクション層は `direction` で片方だけを敷きます。** 左右を同時に敷くと、カード面が大きくずれた
  ときに両方が露出します（左へ深く引くと削除ボタンの隣に完了色が出る、右へ抜けきると右端に削除ボタンが
  現れる）。見た目が壊れるだけでなく、**押しても何も起きない領域**ができて操作が成立しなくなります。
- **アクションの当たり判定は露出しうる領域の全体に持たせます。** ラベルの矩形だけをボタンにすると、
  スナップ位置より深くスワイプしたときに反応しない帯ができます。
- **カード根 div の `transform` は @dnd-kit が使用中**（`SortableTaskCard` の `dragStyle`）。
  スワイプの `translateX` は必ずカード面（内側）に当てます。
- **静止時はカード面に `transform` を残しません。** カード内には portal しない要素があり、
  `transform` が載っていると `position: fixed` の containing block がカードになって描画位置が壊れます。
  同じ理由で定量タスクの進捗モーダルは `createPortal` で `document.body` へ出しています。
- **`overflow-hidden` はスワイプ中だけ掛けます。** 常時掛けると三点メニューのドロップダウンが切れます。
- 変位は React state ではなく DOM へ直接書きます（`touchmove` ごとの再描画を避けるため）。
  state は「背景層を見せるか」「しきい値に達したか」など離散的なものだけです。
- `preventDefault()` が要るので **native の `addEventListener` を使います**。React の `onTouchMove` は
  ルートに passive で登録されるため `preventDefault()` が効きません（`BottomSheet` と同じ理由）。
- ばね戻しは `transitionend`、登場アニメは `animationend` で後始末しますが、**値が変わらないと
  `transitionend` は飛ばず、非表示タブでは `animationend` も来ません**。`overflow-hidden` が残ると
  三点メニューが切れるため、どちらもタイマーの保険を併用しています。
- 時間の定数は 2 箇所で二重管理です。`TaskCard.tsx` の `FLY_IN_MS` と `global.css` の
  `.task-fly-in` の duration は同値に保ってください。

### フィードバック

しきい値到達は**アイコンの拡大（視覚）で必ず伝えます**。ハプティクスも鳴らしますが、
iOS では無音になるため（[ハプティクス](#ハプティクスusehaptic)）操作結果を伝える唯一の手段にはしません。
`prefers-reduced-motion: reduce` のときはばね戻しのアニメーションを省き、即座に静止位置へ戻します。

### 未実装（既知）

- 繰り返しタスクの延期（別列と Worker 側の対応が要るため、意図的に対象外）。
- デスクトップ（マウス）では無効です。`touchstart` しか扱わないため、画面幅ではなく入力方式で分かれます。
- メモカードには延期がありません（[通知に一切関与しない](#通知には一切関与しない)ため）。

| 完了ヒートマップ | 直近 12 週。1 セル = 1 日、濃淡 5 段階。上部に月ラベル、右カラムに合計 / 週平均 / 完了があった日 / 最も多い日。寸法と凡例の向きは `sm` で切り替わる（後述）。`completions` ベース |
| プロジェクト別内訳 | 直近 30 日。横棒 + 件数。`completions` の `project_name` スナップショットベース |
| 定量タスクの現状 | 一覧 |

### 完了は種別を問わず `completions` に記録する

**繰り返し・非繰り返しを問わず、完了のたびに完了ログを 1 行追記します**（`taskRepo` の `markCompleted`）。
以前は繰り返しタスクだけを記録し、非繰り返しはタスク行の `updated_at` で代用していましたが、
**それだとヒートマップの過去のセルが後から動きます**（完了済みタスクを編集すると `updated_at` が進むため）。
「いつ終わらせたか」は `completions` だけが持つ情報として扱います。

**完了が退いたら完了ログも対で取り下げます。** 対象は完了の取り消し、サブタスクを外したことによる
自動完了の取り消し、完了済み定量タスクを目標未満へ編集、完了済みタスクに未完了の手順を追加、の 4 経路です。
どれか 1 つでも抜けると「未完了に戻したのにセルが濃いまま」になり、やり直すと 1 回の完了がログ 2 件に増えます。

**プロジェクト名は完了時点の値をスナップショットとして焼き付けます**（`CompletionLog.project_name`）。
集計時に `task_id` から現在の `tasks` を引くと、プロジェクトは
[文字列一致による派生表示](#プロジェクト)なのでリネームで過去の内訳が丸ごと書き換わります。

### ヒートマップの寸法と凡例

**セル寸法と gap は `sm`（640px）で切り替えます。** モバイルは 1rem / gap 0.1875rem、`sm` 以上は
1.125rem / gap 0.25rem です。モバイル側の上限は「凡例を右に置いても 375px 端末のカード内側
（309px）に収まること」で決まっています。曜日ラベル列の幅・月ラベル枠の寸法・ラベルの文字サイズも
セルと連動するので、**`sm:` バリアントは必ず全部まとめて変えること**。1 か所でも取り残すと
月ラベルと週の列が横にずれます。gap は月ラベル行 / 曜日ラベル列 / 週の列 / 列を並べる flex の
4 か所で共有するため、定数 `GAP` に切り出してあります。

**凡例は DOM を 1 セットだけ持ち、向きだけ切り替えます。** `sm` 未満はグリッドの右へ縦置き
（`flex-col-reverse` なので上が「多い」）、`sm` 以上はグリッド直下へ横並び（`sm:flex-row` で
左が「少ない」）。DOM 順は「少ない → スウォッチ 5 個 → 多い」で固定なので、向きを二重に
書かずに済み、スクリーンリーダーが同じ文言を 2 回読むこともありません。
モバイルで縦置きにしているのは、グリッドが 12 週ぶんの固定幅しかなく、そのままだとカード右端に
80px 前後の死に余白が残るためです。

`sm` 未満では**余った幅を受け取るのは凡例側**です（グリッドは内容幅のまま、凡例が `flex-1`）。
グリッドを伸ばして凡例を押し出すと、凡例が余白の中央ではなくカードの右端に貼り付いて見えます。
凡例の `basis` は 0 なので、グリッドが溢れる幅でも縮小の割り当てはグリッド側だけに行き、
凡例は潰れません。**スウォッチはセルと同じ寸法（`CELL` を共有）** です。凡例だけ小さいと、
実際の濃さを見比べる用途に足りません。

縦置きの凡例には**月ラベル行と同じ高さの `mt`（13px）** を与えています。`items-center` は
マージン込みで中央に置くので、これで下へその半分ぶん動き、凡例の中心がラベル行を含む全体では
なくマス目の中心に揃います。**月ラベル行の高さを変えたらこの `mt` も変えること**（放置すると
凡例だけ上下にずれます）。

**右端の列には「今週」と出します。** 右端が現在であることは他のどこにも書かれておらず、
読み取る手がかりがありませんでした。月ラベル行に相乗りするので高さは増えません。
色は月名の灰色ではなくブランド色（カード見出しのアイコンと同じ）で、月の並びの続きに
見えないようにしています。**今週が月の変わり目に当たった週は「今週」を優先して月名を伏せます**
（月名は前後の列から追えますが、どこが今週かはこのラベルにしか出ません）。

**0 件セルは `slate-200` です。** カードに背景色は無くページ地色（ライト `slate-50` /
ダーク `slate-950`）がそのまま透けるため、`slate-100` ではライトでコントラスト比 1.05:1
しかなく升目が消えます（`slate-200` で 1.18:1、ダークの `slate-800` は元から 1.38:1）。
**枠線は使いません** — 塗りの濃さだけで段階を表し、未到来セル（塗りも枠も無い空きマス）が
0 件のマスと区別できる状態を保ちます。

### 既知の制約: 簡易集計

- **完了履歴はサーバーへ同期しません**（[data-model.md](./data-model.md#completions-が別ストアな理由)）。
  ストリーク・ヒートマップ・内訳は端末ごとに違う値になります。仕様なので、レポート見出しの下に
  「この端末に残っている記録から集計しています」と明示しています
- **記録範囲を広げる前の非繰り返しタスクの完了は入っていません**（バックフィルしていない。
  過去の `updated_at` から復元しても、完了後に編集された行は日付がずれた不正確な過去になるため）
- **週間達成率の分母は「今週更新されたタスク数」**（メモは除外する。完了しないので数えると分母だけ増える）。
  プロジェクト名変更は対象タスク全件の `updated_at` を進めるため、大きいプロジェクトをリネームした
  直後は今週の達成率が一時的に歪む（次週で解消。**ヒートマップと内訳は `completions` ベースなので歪まない**）
- **ソフト削除したタスクの完了はヒートマップ・内訳に残ります**（完了した事実は削除で消えない）。
  実際に消えるのは「データ管理」の手動クリーンアップで孤児ログが回収されたときです
- ヒートマップのしきい値は固定（0 / 1-2 / 3-4 / 5-7 / 8+）。ユーザーの平均から相対で決めると、
  今日の完了数が増えただけで過去のセルの色が一斉に変わる
- **ヒートマップ右カラムの分母は「経過日数」**（= まだ来ていない日を除いた描画済みセル数）。
  週平均は `合計 ÷ 経過日数 × 7`、「完了があった日」は `N 日（経過日数 中）`。
  週数（12）で割ると今週が途中のぶん週初に必ず下振れするため、日数から週へ換算している

### QR による端末追加

12 桁の手入力が初回体験の摩擦点だったため、1 台目が QR を表示し 2 台目が読み取る経路を追加しています。手入力の経路は残してあります（読み取れない環境のフォールバック）。

- **QR に載せるのは同期コードの生文字列 12 文字だけです。** アプリの URL は載せません。同期コードは bearer credential なので、URL に載せると履歴・Referer・アクセスログに残る経路ができます（[security.md](./security.md#qr-による端末追加)）。
- **QR の読み取りは `switchSyncCode()` の確認経路を迂回しません。** `SyncQrScanner` は同期を実行せず、読み取った値を返すだけです。実行は手入力と同じ確認ダイアログ →`switchSyncCode()` を通ります。全件がサーバーに書けたことを検証してからローカルを差し替える保全ロジック（[sync.md](./sync.md)）を回避してはいけません。
- 確認ダイアログには読み取ったコードを `ABCD-2345-EFGH` 形式で表示します（誤読の目視検知）。
- 生成は `qrcode-generator`、読み取りは `jsqr`。**どちらも動的 import** し、設定画面を開くまで読み込みません。CDN は使いません（オフラインで動く必要があるため）。両チャンクとも Workbox の precache manifest に入ります（2026-08-16 に `dist/sw.js` で実測確認）。
- QR は英数字モード・誤り訂正 Q で生成するため version 1（21×21）に収まります。既定の Byte モードだと 12 バイトが version 1-Q の上限 11 バイトを超えて version 2 に上がるため、`addData` にモードを明示しています。
- **QR は白地・黒モジュール固定です。** ダークモードでも反転させません（反転した QR を読めないリーダーがあるため）。クワイエットゾーン 4 モジュールを `viewBox` に含めて白で塗ります。
- カメラ映像は端末内の `<canvas>` で処理するだけで、どこにも送信しません。`facingMode` は `ideal: 'environment'`（`exact` にすると背面カメラの無い PC で `OverconstrainedError` になる）。`<video>` には `playsInline` / `muted` / `autoPlay` が必須です（iOS Safari のインライン再生）。
- 同期コードとして妥当でない QR を読んだ場合は、スキャナを閉じずに案内を出して読み取りを続けます（他アプリの QR を写しただけの可能性が高いため）。

## PWA・モバイル対応

### マニフェスト（`public/manifest.webmanifest`）

- `display: standalone` / `orientation: portrait` / `theme_color: #3D7C77`
- アイコンは 192 / 512 の 2 種類のみ（`purpose: any maskable` 兼用）。`apple-touch-icon` と
  通知の `badge` も `icon-192.png` を流用

### iOS Safari

- `apple-mobile-web-app-capable` / `apple-mobile-web-app-status-bar-style: black-translucent` /
  `apple-mobile-web-app-title: ToDo` を `index.html` に設定
- **iOS は PWA インストール後でないと Web Push を受信できません。** `MobilePwaGuide` でホーム追加を促します
  （`todo_ios_pwa_dismissed` フラグで 1 回 dismiss 可）
- `viewport-fit=cover` + Tailwind の `safe-top`（`global.css` 定義）でノッチ対応

### Android

- `mobile-web-app-capable` / `theme-color: #3D7C77`
- Chrome のインストールプロンプトが標準で出る

### ハプティクス（`useHaptic`）

- Android / Chromium では Vibration API を利用する
- iOS を含む非対応環境では無音になる。ハプティクスは補助的な体験であり、操作結果を伝える唯一の手段にしない

## セキュリティ関連のメモ

- `?task=` はタスクへのスクロールに使う。URL 値を DOM セレクタや遷移先に使う変更では、エスケープと入力の扱いを再確認する。
- `public/_headers` は現時点で存在せず、CSP などの追加ヘッダーは実装されていない。ヘッダーを追加・変更する場合は [security.md](./security.md) と実際の Pages 設定を確認する。
- XSS 対策の確認を「過去の grep 結果」だけに依存しない。HTML を直接扱うコードや外部 URL を追加する変更では、対象実装をレビューする。
